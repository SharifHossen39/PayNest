# Frontend PRD reconciliation

Sources: [final frontend PRD](../../prds/prd-Java-PayNest-2026-10-19/prd.md), [handoff addendum](../../prds/prd-Java-PayNest-2026-10-19/addendum.md), and latest decisions in the PRD memlog. Target: [draft architecture spine](ARCHITECTURE-SPINE.md).

Verdict: no source incompatibilities or missing load-bearing requirements found. This is source reconciliation, not final architecture approval. FE-AQ-1 intentionally remains open; AD-16 proposes sessionStorage and explicitly requires user acceptance of its script-readable credential exposure. This report neither endorses nor resolves that proposal.

| Source constraint | Architecture treatment |
|---|---|
| Purpose, six screens, seven APIs, learning-first scope and exclusions | AD-13 and inherited AD-1..12 retain the six routes, existing monolith/database/entities, local-only sign-out, manual funding and no added product operations or infrastructure. AD-14 uses concrete ownership without mandatory service hierarchies or global state framework. |
| FE-FR-1..2: account creation and sign-in | AD-19 preserves backend-compatible Unicode validation, exact passwords, clearing after completion/navigation and no signup-only password policy on signin. AD-20 binds the approved UX, including signup confirmation without authentication and generic invalid-credential handling. AD-17 separates public signin 401 from protected authentication loss. |
| FE-FR-3 / FE-UJ-4: reload and authentication lifecycle | AD-16 retains the existing credential and expiry, verifies current identity before private rendering, and documents tab/restart behavior and storage failure. AD-17 clears private state and gates late responses by generation; expiry/sign-out/current protected 401 cannot be undone by delayed responses. No refresh, revocation or silent cookie/BFF capability is added. FE-AQ-1 is the explicit remaining review decision. |
| FE-FR-4: Dashboard truthfulness | AD-19 keeps identity/Wallet reads independent and distinguishes loading, missing data, actual zero, stale refresh data and errors. AD-17 prevents prior-identity data from returning. |
| FE-FR-5: exact transfer input and conservative completion | AD-15 validates exact input before normalization and preserves numeric wire types. AD-18 requires inline review, one confirmed dispatch, validated 201 plus COMPLETED, known rejection versus unknown outcome, explicit fresh action and no retry/queue/replay. Confirmed success remains confirmed if a subsequent read fails. |
| FE-FR-6..7: history and participant receipts | AD-19 uses actual page fields, default page0/size20, bounded navigation, successful-page replacement and fixed backend ordering. AD-15 preserves positive int64 route IDs. AD-19 clears prior-ID detail and retains identical unknown/inaccessible 404 presentation. AD-20 binds the required receipt facts and viewer-relative directions. |
| FE-FR-8: feedback and navigation | AD-13/17/19/20 retain guarded navigation, pending states, explicit read retry, safe ApiError/code/field mapping and fallback summaries without exposing database/framework details. |
| FE-NFR-1: responsive/accessibility | AD-20 binds approved tokens, keyboard/focus/live-region behavior, native semantics, 44px controls, 320px reflow and 200% zoom. AD-22 includes browser interaction verification. |
| FE-NFR-2 and addendum: full-range numeric transport | AD-15 selects text HTTP responses, lossless-json parsing/serialization, validated decimal-string money and ID models. Maximum money, unsafe-integer IDs, int64 totals, extra fractional zeros and raw numeric JSON fixtures are covered by AD-15/22. No already-rounded Number conversion or browser-authoritative balance arithmetic is permitted. |
| FE-NFR-3: privacy and API-scoped credentials | AD-16..18 exclude persisted private payloads and passwords, scope bearer injection to exact protected operations on the intended origin, preserve Angular escaping, and gate responses from older sessions. Bundle-visible configuration cannot introduce backend secrets under inherited AD-12. |
| FE-NFR-4: meaningful verification | AD-22 covers forms/state, reload/expiry/sign-out/401, storage denial, late responses, precision, duplicate confirmation, ambiguous transfers, pagination/ownership and the six-screen real-backend smoke with manual/test-only funding. |
| FE-NFR-5 and addendum: browser integration and delivery | AD-21 chooses a development API proxy and packaged same-origin static SPA in the existing JAR, excludes reserved/API paths from fallback and preserves default-deny API behavior. Ordinary backend work stays independent of Node. AD-22 verifies proxy, packaged deep links/assets and unchanged OpenAPI operation count. |

No product decision was reopened and no implementation was performed. Historical reconciliation wording about unresolved reload authentication is superseded by the finalized PRD and latest memlog decision; only the storage-risk proposal remains intentionally pending here.
